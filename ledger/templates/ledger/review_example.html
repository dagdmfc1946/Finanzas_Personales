Caso ficticio para aprender. Estos ejemplos no son movimientos guardados ni cambian tus saldos. Sigue el orden de Revisar esta fase para comprender cómo se conectan.

{% if section == 'organizacion' %}

1. Prepara el espacio

  1. Actividad Personal / trabajo principal y otra llamada Emprendimiento de ejemplo.
  2. Cuenta Banco de ejemplo, tipo Banco, saldo inicial de 1.000.000 COP en la actividad personal.
  3. Cuenta Efectivo de ejemplo, saldo inicial cero. Categorías Sueldo (ingreso), Ventas (ingreso) y Mercado (gasto).

Resultado esperado: saldo total 1.000.000 COP. El saldo inicial no cuenta como ingreso.

{% elif section == 'movimientos' %}

2. Registra una sola vez cada operación

  1. Ingreso Cobro de sueldo de ejemplo: 2.000.000 COP, actividad personal, cuenta Banco de ejemplo, categoría Sueldo.
  2. Ingreso Venta de ejemplo: 300.000 COP, actividad Emprendimiento de ejemplo, misma cuenta, categoría Ventas.
  3. Gasto Mercado de ejemplo: 250.000 COP, actividad personal, cuenta Banco de ejemplo, categoría Mercado.
  4. Transferencia Retiro de efectivo de ejemplo: 100.000 COP, del banco al efectivo; actividad personal en origen y destino, sin categoría.

Resultado esperado: ingresos 2.300.000 COP, gastos 250.000 COP y saldo total 3.050.000 COP. La transferencia no crea ingresos ni gastos. Puedes usar una fecha del mes que revisas y buscar «ejemplo».

Para probar una corrección, cambia Mercado a 260.000 COP con motivo «Corregir importe de ensayo»: el saldo sería 3.040.000 COP. Restáuralo a 250.000 con otro motivo para continuar el caso. Para probar anulación, crea y anula un gasto separado de 10.000 COP; el saldo regresa al valor anterior y queda el historial.

{% elif section == 'sueldo' %}

3. Planea y relaciona el cobro

  1. Planear sueldo: concepto Sueldo de ejemplo, actividad personal, modalidad Neto, importe 2.000.000 COP.
  2. Mes trabajado agosto de 2026; fecha prevista de cobro 5 de septiembre de 2026; mes presupuestado septiembre de 2026. Son tres datos independientes.
  3. Consulta septiembre y pulsa Vincular ingreso existente. Selecciona el ingreso Cobro de sueldo de ejemplo registrado en Movimientos.

Resultado esperado: previsto 2.000.000 COP, cobrado 2.000.000 COP y pendiente cero. El saldo total sigue en 3.050.000 COP: vincular no vuelve a sumar el sueldo.

Alternativa para el mismo plan: modalidad Bruto y deducciones, neto vacío, bruto 2.200.000, adicionales 100.000 y deducciones 300.000 COP. Calcula el mismo neto; corrige el plan con motivo, no crees otro si quieres comparar el mismo caso.

Para ensayar pagos parciales usa, en lugar del ingreso único, dos ingresos de 1.200.000 y 800.000 COP. Con solo el primero vinculado el pendiente es 800.000; con ambos, cero. No registres ambas alternativas a la vez. Desvincular exige motivo y conserva el ingreso; anular un ingreso vinculado lo excluye del cobro.

{% elif section == 'resumen' %}

4. Comprueba el resultado

Después del caso de Actividades y cuentas → Movimientos → Mi sueldo:

  • Consolidado: ingresos 2.300.000 COP, gastos 250.000 COP, saldo 3.050.000 COP.
  • Banco de ejemplo: 2.950.000 COP. Efectivo de ejemplo: 100.000 COP.
  • Actividad personal: saldo asignado 2.750.000 COP. Emprendimiento: 300.000 COP.

Selecciona cada actividad y vuelve a Consolidado para comparar. El sueldo previsto no aumenta el dinero y el retiro entre cuentas propias no cambia el total.

{% elif section == 'historial' %}

5. Comprende una corrección

Busca el evento del gasto Mercado de ejemplo corregido de 250.000 a 260.000 COP. Despliega el registro: verás el motivo y los valores antes/después. En esta vista técnica los importes están en centavos: 25.000.000 y 26.000.000 equivalen a esos importes en COP.

Al devolver el gasto a 250.000 se añade otro evento. Una anulación conserva el registro; un vínculo de sueldo y su desvinculación también dejan antecedentes. No esperes eventos ficticios aquí si no has realizado esas operaciones.

{% elif section == 'respaldo' %}

6. Guarda el punto de revisión

  1. Al terminar el caso, pulsa Crear y descargar respaldo. Conserva el JSON en una carpeta privada.
  2. La copia incluye las dos actividades, las cuentas, movimientos y el plan de sueldo con su cobro. Conserva también los antecedentes.
  3. Para ensayar restauración utiliza una instalación de ensayo separada siguiendo el manual, sección 10. No restaures un ejemplo sobre datos personales.

Resultado esperado tras recuperar esa copia en ensayo: saldo 3.050.000 COP, sueldo cobrado 2.000.000 COP y pendiente cero. La restauración reemplaza los datos financieros y conserva el acceso de la instalación receptora.

{% elif section == 'revision' %}

Recorrido de ejemplo, en orden

  1. Actividades y cuentas: dos actividades, banco con saldo inicial y efectivo.
  2. Movimientos: sueldo, venta secundaria, mercado y transferencia; corrección/anulación con motivo.
  3. Mi sueldo: plan neto o detallado, meses distintos y vínculo del ingreso existente. Consulta septiembre de 2026 para este ejemplo.
  4. Resumen: compara saldo total, cuentas y actividades.
  5. Historial: abre antes/después y verifica motivos.
  6. Respaldos: descarga la copia; recupera únicamente en ensayo.
  7. Acceso: cierra sesión y vuelve a entrar con tu usuario. No necesitas crear otro usuario para revisar. No cambies credenciales solo para seguir este caso.

Cada sección tiene su propio ejemplo desplegable y resultado esperado. Las cifras corresponden a un caso que empieza vacío; si ya tienes datos, no esperes esos mismos totales ni añadas el ejemplo a tu registro personal. Puedes leerlo como guía. Los formularios reales guardan cambios cuando pulsas Guardar.

Comprueba también que texto, botones, filtros y navegación sean cómodos en tu pantalla. Las casillas de revisión son temporales. Presupuestos y recurrencias siguen pendientes; ahorro, préstamos y simulador corresponden a Fase 4 y no se simulan como funciones terminadas.

{% endif %}
